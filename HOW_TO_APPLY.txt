HOW TO APPLY
============
1. Close Godot.
2. Extract over your project root (diff against f59bf51).
3. Reopen.

HOW TO USE IT
-------------
Play a test day, then press F10 and click "Export Diagnostic Run".
It writes debug/latest/ and debug/archive/YYYY-MM-DD-HHMM/, then commit them.

Before exporting you can set Test purpose / Developer notes / Expected result
on Managers/DiagnosticRunExporter in the inspector - they appear in
RUN_SUMMARY.md. No new UI was built for this, as requested.

REVIEW ORDER
------------
  1. RUN_SUMMARY.md          overall PASS/WARN/FAIL + which system broke
  2. drinks_report.txt       full chain per drink
  3. stock_report.txt        authoritative vs displayed, plus stock events
  4. staff_report.txt        tasks + navigation trouble by destination
  5. customer_report.txt
  6. system_diagnostics.txt  navigation scan + station stock plans

VERIFY
------
  godot --headless res://tests/diagnostic_export_probe.tscn   -> 40 / 0

NOTE ON res://
--------------
Reports are written under res://debug so they land in the repository. That is
editor-only by design; an exported build cannot write there and will log a
clear error rather than failing silently. Players never write diagnostics.

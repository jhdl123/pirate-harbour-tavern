Diagnostic report accuracy fixes — three files

Your first committed run (dd2331b) exposed three defects in MY reporting.
The gameplay was fine; the tool was lying.

  systems/diagnostics/diagnostic_run_exporter.gd
    1. The stock report called count_item() with a CONTENT id where a STOCK
       ITEM id is wanted. It silently returned 0 and reported every healthy
       display as "FAIL — authoritative and displayed quantities disagree",
       while RUN_SUMMARY said Storage PASS. It now resolves the stock item
       (grog_barrel, small_beer_cask, port_wine_crate...) and prints it, and
       treats "more stored than the pile can show" as PASS rather than a
       mismatch.
    2. Days always read 0 — it looked for a `current_day` property; WorldTime
       exposes get_day(). Now reads 1 correctly.

  systems/staff/diagnostics/staff_report_manager.gd
    3. get_summary() read TaskBoard's report under a "totals" key that does
       not exist, so tasks_created / completed / cancelled were all 0 while
       the same report's summary line said "125 done". It now returns
       TaskBoard's own "summary" section wholesale, so a metric added there
       appears here with no second naming scheme to drift.

  tests/diagnostic_export_probe.gd
       + _check_reports_agree(): stocks every storeroom prop, then asserts the
       stock report contains no FAIL and that staff metrics resolve. 59
       assertions. This is the check that was missing — two reports disagreeing
       about one fact is exactly what this system exists to catch.
